# Требования к модулю «Курсы»

---

## 1. Структура курса

Курс имеет иерархическую структуру:

```
Курс
└── Блок (раздел)
    ├── Урок 1
    ├── Урок 2
    ├── Урок N
    └── Практика по блоку
```

**Курс** — верхнеуровневая единица обучения. Содержит мета-информацию и набор блоков.

**Блок** — тематический раздел курса. Содержит упорядоченный список уроков и одну итоговую практику по всему блоку.

**Урок** — минимальная единица обучения. Содержит теоретический материал.

**Практика по блоку** — задание, закрепляющее материал всех уроков блока. Доступна только после прохождения всех уроков блока.

---

## 2. CRUD курса

### 2.1 Создание курса

- Принимает: название, описание, уровень сложности, теги, список блоков (опционально).
- Курс создаётся со статусом `draft`.
- Блоки, уроки и практики могут быть переданы вложенной структурой при создании или добавлены отдельными запросами позже.

### 2.2 Получение курса

- Получение по идентификатору.
- Ответ содержит полную структуру курса: блоки → уроки → практики по блокам.

### 2.3 Обновление курса

- Обновление мета-информации курса (название, описание, сложность, теги, статус).
- Отдельные эндпоинты для управления блоками, уроками и практиками внутри курса.
- При обновлении порядка блоков или уроков принимается массив идентификаторов в нужном порядке.

### 2.4 Удаление курса

- Мягкое удаление (soft delete) — курс помечается как удалённый, не исчезает физически.
- Каскадное скрытие всех блоков, уроков и практик курса.

---

## 3. Получение списка курсов с пагинацией

- Поддержка курсорной или офсетной пагинации.
- Параметры запроса:
  - `page` / `cursor` — текущая страница или курсор.
  - `limit` — количество курсов на страницу.
  - `status` — фильтр по статусу (`draft`, `published`, `archived`).
  - `difficulty` — фильтр по уровню сложности.
  - `tags` — фильтр по тегам.
  - `search` — полнотекстовый поиск по названию и описанию.
  - `sort` — сортировка (по дате создания, названию, популярности).
- Ответ содержит: массив курсов, общее количество, информацию о следующей странице.

---

## 4. Прохождение курса

### 4.1 Запись на курс

- Пользователь записывается на курс — создаётся запись о прогрессе.
- Прогресс хранит: текущий блок, текущий урок, процент завершения, статус (`in_progress`, `completed`).

### 4.2 Навигация по курсу

- Следующий урок открывается только после отметки текущего как пройденного.
- Практика по блоку открывается только после прохождения всех уроков этого блока.
- Следующий блок открывается только после выполнения практики по текущему блоку.
- Поддерживается возврат к уже пройденным урокам и блокам в любое время.

### 4.3 Отметка урока как пройденного

- Пользователь явно фиксирует завершение урока.
- Прогресс обновляется, разблокируется следующий шаг.

### 4.4 Завершение курса

- Курс считается завершённым, когда пройдены все блоки и выполнены все практики.
- Фиксируется дата завершения.

---

## 5. Выполнение практики

### 5.1 Начало практики

- Пользователь начинает практику — создаётся попытка (`attempt`) со статусом `in_progress`.
- Хранится время начала попытки.

### 5.2 Отправка ответа

- Пользователь отправляет выполненное задание (текст, код, файл — в зависимости от типа практики).
- Создаётся запись ответа, привязанная к попытке.

### 5.3 Проверка практики

- Автоматическая проверка — если практика поддерживает авто-проверку (тесты, задания с вариантами ответа).
- Ручная проверка — наставник или система проверяет ответ вручную и выставляет оценку.
- После проверки попытка переходит в статус `passed` или `failed`.

### 5.4 Повторная попытка

- При статусе `failed` пользователь может начать новую попытку.
- Хранится история всех попыток с результатами.

### 5.5 Завершение блока

- После успешного прохождения практики блок считается завершённым.
- Открывается следующий блок.

---

## 6. Генерация курса

### 6.1 Запрос на генерацию

- Принимает: тему курса, целевую аудиторию, уровень сложности, желаемое количество блоков и уроков в каждом блоке.
- Генерация запускается асинхронно — сразу возвращается идентификатор задачи.

### 6.2 Статус генерации

- Отдельный эндпоинт для проверки статуса задачи генерации.
- Статусы: `pending`, `in_progress`, `completed`, `failed`.
- При `completed` — возвращается идентификатор созданного курса.

### 6.3 Что генерируется

- Структура курса: блоки с названиями и описаниями.
- Уроки внутри каждого блока: название, теоретический контент.
- Практика для каждого блока: задание, критерии оценки.

### 6.4 Редактирование после генерации

- Сгенерированный курс создаётся со статусом `draft`.
- Весь сгенерированный контент доступен для редактирования через стандартный CRUD.

---

## 7. Управление блоками и уроками

### 7.1 Блоки

- Добавление блока в курс.
- Обновление блока (название, описание).
- Удаление блока (каскадно удаляет уроки и практику блока).
- Изменение порядка блоков внутри курса.

### 7.2 Уроки

- Добавление урока в блок.
- Обновление урока (название, контент).
- Удаление урока.
- Изменение порядка уроков внутри блока.

### 7.3 Практика блока

- Добавление практики к блоку (один блок — одна практика).
- Обновление практики (задание, критерии, тип проверки).
- Удаление практики.

---

## 8. Статусы курса

| Статус      | Описание                                              |
|-------------|-------------------------------------------------------|
| `draft`     | Курс в разработке, недоступен для прохождения         |
| `published` | Курс опубликован, доступен для записи и прохождения   |
| `archived`  | Курс архивирован, недоступен для новых записей        |

---

## 9. Ограничения и правила

- Нельзя опубликовать курс без хотя бы одного блока с уроками.
- Нельзя опубликовать блок без хотя бы одного урока.
- Практика по блоку не является обязательной при публикации, но рекомендуется.
- Порядок блоков и уроков явный — хранится как числовое поле `position`.
- Удаление курса в статусе `published` недоступно — сначала необходимо перевести в `archived`.
