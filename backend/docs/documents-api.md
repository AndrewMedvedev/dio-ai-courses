## Общая информация

Базовый префикс API:

```text
/api/v1
```

Все endpoint-ы документов требуют JWT access token:

```http
Authorization: Bearer <access_token>
```

Запросы отправляются как `multipart/form-data`, потому что оба endpoint-а принимают файл в поле `file`.

Для доступа используется проверка:

```python
authorize(identity, CREATE)
```

Требуемое право: `course:create` (`CREATE`) — создание курса. Право может быть выдано в scope `organization` или `own`.

Идентификатор пользователя не передаётся в запросе. Сервер получает его из JWT (`identity.id`) и использует при сохранении загруженного документа.

## Краткий список HTTP-эндпоинтов

| Метод | URL | Успешный статус | Требуемое право | Назначение |
| --- | --- | --- | --- | --- |
| `POST` | `/api/v1/documents/to/markdown` | `200 OK` | `course:create` | Конвертирует загруженный файл в Markdown и возвращает Markdown-строку без сохранения |
| `POST` | `/api/v1/documents/upload` | `201 Created` | `course:create` | Конвертирует файл в Markdown, разбивает его по заголовкам и сохраняет как иерархию документа пользователя |

## Поддерживаемые файлы

Оба endpoint-а принимают только файлы со следующими расширениями:

| Расширение | Тип содержимого |
| --- | --- |
| `.pdf` | PDF-документы |
| `.docx` | Microsoft Word |
| `.pptx` | Microsoft PowerPoint |
| `.xlsx` | Microsoft Excel |
| `.md` | Markdown |
| `.html` | HTML |
| `.txt` | Plain text |
| `.json` | JSON |

Расширение определяется по имени файла из `UploadFile.filename`:

```python
Path(file.filename).suffix.lower()
```

Проверяется именно расширение файла, а не MIME type.

Максимальный размер файла: `30 МБ`.

Файл читается потоково порциями по `1 МБ`. Если общий размер превышает лимит, чтение прерывается и возвращается ошибка `413 Payload Too Large`.

## Конвертация документа в Markdown

```http
POST /api/v1/documents/to/markdown
```

**Успешный статус:** `200 OK`
**Content-Type запроса:** `multipart/form-data`
**Content-Type ответа:** `application/json`, строковое значение
**Требуемое право:** `course:create` (`CREATE`)

### Зачем нужен

Endpoint принимает файл, конвертирует его содержимое в Markdown и сразу возвращает результат клиенту.

Файл не сохраняется в базе данных и не привязывается к пользователю. Этот endpoint подходит для предпросмотра, проверки результата конвертации или подготовки текста на стороне клиента.

### Поля запроса

| Поле | Тип | Обязательное | Значение |
| --- | --- | ---: | --- |
| `file` | `UploadFile` | да | Файл с одним из поддерживаемых расширений |

### Пример запроса

```bash
curl -X POST 'http://localhost:8001/api/v1/documents/to/markdown' \
  -H 'Authorization: Bearer <access_token>' \
  -F 'file=@/path/to/document.pdf'
```

### Пример успешного ответа

FastAPI сериализует строку как JSON string:

```json
"# Введение\n\nТекст документа в формате Markdown."
```

Если клиент автоматически десериализует JSON, он получит обычную строку:

```text
# Введение

Текст документа в формате Markdown.
```

### Как работает

1. Проверяет право `course:create` у текущего пользователя.
2. Определяет расширение файла по имени.
3. Проверяет, что расширение входит в список разрешённых.
4. Читает файл с ограничением `30 МБ`.
5. Возвращает ошибку `400 Bad Request`, если файл пустой.
6. Конвертирует файл в Markdown через `MarkItDown` в отдельном thread executor, чтобы не блокировать event loop.
7. Возвращает Markdown-строку.

## Загрузка документа в базу знаний пользователя

```http
POST /api/v1/documents/upload
```

**Успешный статус:** `201 Created`
**Content-Type запроса:** `multipart/form-data`
**Content-Type ответа:** `application/json`
**Требуемое право:** `course:create` (`CREATE`)

### Зачем нужен

Endpoint загружает пользовательский документ во внутреннюю иерархическую таблицу `documents`.

После загрузки содержимое документа становится доступно инструментам агентов курса, которые могут искать по документам пользователя и использовать их как контекст при создании курса.

### Поля запроса

| Поле | Тип | Обязательное | Значение |
| --- | --- | ---: | --- |
| `file` | `UploadFile` | да | Файл с одним из поддерживаемых расширений |

### Пример запроса

```bash
curl -X POST 'http://localhost:8001/api/v1/documents/upload' \
  -H 'Authorization: Bearer <access_token>' \
  -F 'file=@/path/to/course-materials.docx'
```

### Пример успешного ответа

```json
{
  "message": "Файл загружен"
}
```

### Как работает

1. Проверяет право `course:create` у текущего пользователя.
2. Определяет расширение файла по имени.
3. Проверяет, что расширение входит в список разрешённых.
4. Читает файл с ограничением `30 МБ`.
5. Возвращает ошибку `400 Bad Request`, если файл пустой.
6. Конвертирует файл в Markdown через `MarkItDown`.
7. Удаляет markdown-ссылки на media-вложения формата `![alt](media://<uuid>)`, оставляя `alt`-текст.
8. Разбивает Markdown на фрагменты по заголовкам уровней `H1`–`H4`.
9. Сохраняет результат в таблицу `documents` для пользователя `identity.id`.
10. Коммитит транзакцию и возвращает сообщение об успешной загрузке.

## Ошибки

### `400 Bad Request` — недопустимое расширение

Возвращается, если расширение файла не входит в список разрешённых.

Пример ответа:

```json
{
  "detail": "Недопустимое расширение файла: '.zip'. Разрешены: .docx, .html, .json, .md, .pdf, .pptx, .txt, .xlsx"
}
```

Если имя файла не содержит расширения:

```json
{
  "detail": "Недопустимое расширение файла: 'не указано'. Разрешены: .docx, .html, .json, .md, .pdf, .pptx, .txt, .xlsx"
}
```

### `400 Bad Request` — пустой файл

Возвращается, если файл успешно прочитан, но его содержимое пустое.

```json
{
  "detail": "Файл пустой"
}
```

### `401 Unauthorized`

Возвращается, если запрос не содержит валидный JWT access token.

Точный формат ответа зависит от IAM middleware/dependencies проекта.

### `403 Forbidden`

Возвращается, если пользователь аутентифицирован, но у него нет права `course:create`.

Точный формат ответа зависит от IAM-политик проекта.

### `413 Payload Too Large`

Возвращается, если размер файла превышает `30 МБ`.

Доменная ошибка:

```text
PAYLOAD_TOO_LARGE
```

Публичное сообщение:

```text
Размер запроса превышает допустимый лимит
```

### Ошибки конвертации

Если `MarkItDown` не сможет обработать файл с разрешённым расширением, endpoint вернёт серверную ошибку. В текущей реализации отдельная пользовательская ошибка для сбоя конвертации не задаётся.

## Как загруженный документ сохраняется

При загрузке через `/api/v1/documents/upload` документ сохраняется как дерево в таблице `documents`.

Основные поля узла:

| Поле | Значение |
| --- | --- |
| `owner_id` | ID пользователя из JWT |
| `parent_node_id` | Родительский узел дерева или `null` для корня |
| `node_type` | Тип узла: `TOC`, `HEADING` или `TEXT` |
| `title` | Заголовок для узлов оглавления и разделов |
| `content` | Текст для leaf-узлов типа `TEXT` |

### Структура дерева

Если в Markdown есть заголовки, сервис создаёт цепочку узлов по заголовкам `H1`–`H4`:

```text
TOC / H1
└── HEADING / H2
    └── HEADING / H3
        └── TEXT
```

Если заголовков нет, создаётся корневой `TOC`-узел с названием исходного файла, а текст сохраняется дочерним `TEXT`-узлом:

```text
TOC / <file_name>
└── TEXT
```

Пустые фрагменты и фрагменты, состоящие только из markdown-заголовка без текста, не сохраняются.

## Ограничения текущей реализации

- Нет отдельного endpoint-а для просмотра списка загруженных документов.
- Нет отдельного endpoint-а для удаления загруженного документа.
- Разрешение проверяется через `course:create`, хотя endpoint работает с пользовательскими документами, а не напрямую с сущностью курса.
- MIME type файла не проверяется; валидация основана на расширении имени файла.
- При повторной загрузке того же файла создаётся новое дерево документа; дедупликация по имени или содержимому не выполняется.
- Endpoint `/upload` возвращает только сообщение об успехе и не возвращает ID созданного корневого документа.
