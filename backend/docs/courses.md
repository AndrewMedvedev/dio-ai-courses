# Модуль `courses`: актуальное устройство и контракты

Документ описывает **текущее рабочее дерево**, а не исторические маршруты. Сведения из прежних README и описания API перенесены сюда как исторический контекст: их `api/v1`, `agents/course_generator`, `application/services` и часть URL уже не соответствуют реализации. Все ссылки ниже относительны к `backend/docs/`. HTTP-префикс `/api/v1` задаёт [регистрация приложения](../src/__init__.py); [роутер courses](../src/courses/api/__init__.py) подключает контексты явно, а пакеты `api/*/v1` используют `include_routers` (кроме явно подключённых generation/knowledge).

## Область ответственности и карта кода

- [Каталог](../src/courses/domain/catalog/entities.py): `Course → Module → Lesson`, порядок через строковый `rank`, блоки урока в `content_blocks`; [enum статусов](../src/courses/domain/catalog/enums.py), [DTO](../src/courses/application/catalog/dtos/), [CRUD-композиция](../src/courses/api/dependencies/catalog/), [HTTP](../src/courses/api/catalog/v1/).
- [Enrollment](../src/courses/domain/enrollment/entities.py): `Member`, `Invitation`, роли и приглашения; [сервис приглашений](../src/courses/application/enrollment/services/invitations.py), [HTTP](../src/courses/api/enrollment/v1/). Уведомление об инвайте публикуется как [событие](../src/courses/domain/enrollment/events.py) и обрабатывается [notifications](../src/notifications/api/v1/handlers.py).
- [Learning](../src/courses/domain/learning/entities.py): прогресс курса/модуля/урока и сессии теории; [HTTP](../src/courses/api/learning/v1/) под `/progress` для прогресса, отдельный `/theory-sessions` для сессий; [RabbitMQ-подписчик](../src/courses/api/learning/v1/broker.py) применяет `LessonProgressUpdated` после проверки задания.
- [Assessment](../src/courses/domain/assessment/entities.py) и [AI endpoint заданий](../src/courses/api/ai/v1/assignment.py): генерация/проверка тестов и практик; [conversations DTO](../src/courses/application/conversations/dtos.py), [внешние агенты](../src/courses/ai/external_agents/) — интервьюер, редактор, ментор, практикер, тестировщик.
- [Knowledge](../src/courses/domain/knowledge/entities.py): дерево пользовательских документов, конвертация и upload через [API](../src/courses/api/knowledge/v1/documents.py), [обработку](../src/courses/infra/docs_processing.py) и [SQL-репозиторий](../src/courses/infra/database/repos/document.py); векторные знания — отдельный [Qdrant-репозиторий](../src/courses/infra/database/repos/vector_repo.py).
- [Generation](../src/courses/ai/generation/): LangGraph-графы курса/модуля/урока; [Taskiq-задачи](../src/courses/infra/tasks.py), [generation sessions](../src/courses/domain/generation/entities.py), [DI](../src/courses/api/dependencies/agents.py). Это не то же самое, что обычный CRUD каталога.

Контракты хранилищ разнесены по `application/<context>/repos`, реализация SQL и маппинг — в [infra/database](../src/courses/infra/database/); [модели](../src/courses/infra/database/models.py) включают `courses`, `modules`, `lessons`, `members`, `course_invitations`, `generation_sessions`, `chats`, `practices`, `documents`, `lesson_theory_sessions`, `course_progress`, `module_progress`, `lesson_progress`. Сессия SQLAlchemy не делает auto-commit: явный `commit` — в CRUD/Transaction, сервисе или задаче. Зависимости FastAPI связывают протоколы с [реализациями репозиториев](../src/courses/api/dependencies/repos.py); общий [Transaction](../src/shared/application/transaction.py) собирает события, коммитит и лишь затем публикует. Пользователи/права приходят из IAM; уведомления — из notifications; LLM — через `llm_service` и внутренний [HTTP-клиент](../src/courses/infra/services/), а не прямой вызов модели.

## Жизненный цикл курса и обучение

1. `POST /courses` создаёт курс с `creator_id` и `organization_id` из identity через [CRUD](../src/courses/api/dependencies/catalog/course.py). [Доменная сущность](../src/courses/domain/catalog/entities.py) по умолчанию имеет `IN_GENERATION`; это **не** статус задачи генерации. Для нового ручного курса обратите внимание на фактический default, не предполагайте `DRAFT`.
2. Модули добавляются в курс, уроки — в модуль. `position` задаёт ровно один `beforeId`/`afterId` либо конец; [ранжирование](../src/courses/domain/catalog/ranking.py) вычисляет строковый ранг между соседями. Создание блокирует соответствующего родителя и проверяет якорь через repo; перемещение [модуля](../src/courses/api/dependencies/catalog/module.py) / [урока](../src/courses/api/dependencies/catalog/lesson.py) блокирует исходный и целевой родительский scope, перечитывает запись, рассчитывает новый rank и коммитит. Разрешён переход между родителями: авторизация endpoint проверяет **исходный** `uid`, но не право на целевой `courseId`/`moduleId` — не считать move полноценным ACL целевого контейнера. Удаление модуля/урока — реальный `DELETE` с commit, без обещания перенумерации; удаление курса переводит его в `ARCHIVED` и возвращает 204.
3. `PATCH /courses/{uid}/status` публикует курс (`PUBLISHED`), `POST /courses/{uid}/invite-only` ставит `INVITE_ONLY`; [change_status](../src/courses/domain/catalog/entities.py) не является полной state machine. Публичный поиск SQL-репозитория [фильтрует опубликованные](../src/courses/infra/database/repos/course.py), а запись на курс [разрешена только для `PUBLISHED`](../src/courses/api/dependencies/enrollment/member.py); приглашение принимает отдельный путь. Роль курса и роль организации — разные сущности.
4. Прогресс создаётся по пользователю на уровне курса, затем модуля, затем урока; [создание урока](../src/courses/api/dependencies/learning/lesson_progress.py) требует существующего прогресса модуля (текст описания endpoint об автосоздании не заменяет эту проверку). `PATCH /progress/lessons/{uid}` отмечает теорию; practice/test отмечаются серверным событием [LessonProgressUpdated](../src/courses/domain/learning/events.py). Теоретические сессии хранят время активности/глубину прокрутки; update проверяет владельца сессии.

## Генерация, повтор и сохранение

[Интервьюер](../src/courses/api/ai/v1/interviewer.py) получает `chatId`, сообщение и контекст из Bearer identity (`course_id`, `organization_id`, `user_id`); для урока дополнительно `moduleId` и `position`. Его инструменты [send_generation](../src/courses/ai/tools/send_generation.py) создают запись `GenerationSession(PENDING, creator_id, generation_key)` и **коммитят её до** отправки Taskiq через `.kicker().with_task_id(task_id).kiq(...)`. Ключи имеют префиксы `course-generation:`, `module-generation:`, `lesson-generation:` и случайный UUID. Ошибка публикации помечает запись `FAILED` и пробрасывается; коммит и брокер не атомарны. Ответ интервьюера — чатовый DTO, а не непосредственно готовый курс. Tool формирует `task_id` и возвращает его модели; [интервьюер](../src/courses/ai/external_agents/interviewer.py) отдаёт клиенту следующий текст модели, поэтому наличие ID в `ChatDTO.content` не гарантировано.

[Задачи](../src/courses/infra/tasks.py) `courses.generate_course`, `courses.generate_module`, `courses.generate_lesson` имеют retry-on-error (до 5, delay 10, timeout 5 часов) и EDGE-отмену; ищут сессию по task ID, коммитят `RUNNING`, запускают граф, затем `COMPLETED`. При `asyncio.CancelledError` — rollback, `CANCELLED`, commit и повторное возбуждение; на обычной ошибке rollback, запись `FAILED` только при `retries_left == 0`, исключение пробрасывается для retry. [API сессий](../src/courses/api/generation/v1/sessions.py) отдаёт состояние/принимает cancel; cancel коммитит `CANCELLING` до `cancellation_backend.cancel(key)`, не означает немедленной остановки удалённого HTTP/LLM-вызова. `GenerationStatus` (`PENDING`, `RUNNING`, `CANCELLING`, `CANCELLED`, `COMPLETED`, `FAILED`) независим от `CourseStatus` (`IN_GENERATION`, `DRAFT`, `INVITE_ONLY`, `PUBLISHED`, `ARCHIVED`).

[Граф курса](../src/courses/ai/generation/course.py): reasoning через reasoner → план структуры `CourseStructure` с валидацией Pydantic → создание и commit курса `IN_GENERATION` → параллельные графы модулей → commit курса как `DRAFT`. [Граф модуля](../src/courses/ai/generation/module.py): план/валидация структуры → сохранение модуля → генерация уроков. [Граф урока](../src/courses/ai/generation/lesson.py): план/валидация `LessonStructure` → генерация типизированных `content_blocks` через theorist → сохранение урока → постановка индексации. На уровне модулей и уроков используются `generate_ranks`/сортировка по `rank`, на уровне блоков — сортировка по исходному `order`; не полагаться на порядок завершения задач. Зависимости на графы собираются [в FastAPI/Taskiq DI](../src/courses/api/dependencies/agents.py).

[Помощник resume](../src/courses/ai/helper.py) читает snapshot по `thread_id`: если `snapshot.next` — `ainvoke(None, durability="sync")`; если есть `snapshot.values`, но нет next — возвращает сохранённый результат **без новой генерации**; иначе запускает с новыми входными данными. Ключи: `course:{course_id}`, `course:{course_id}:module:{rank}`, `course:{course_id}:module:{module_id}:lesson:{rank}`; самостоятельные задачи module/lesson используют те же формы. Для нового запуска с тем же ключом нужен явный reset/versioning всех дочерних threads: повтор интервью/задачи сам по себе не перезаписывает законченный snapshot. Checkpoint не mutex и не гарантия exactly-once.

Состояния графов описаны в `CourseAgentState`/`ModuleAgentState`/`LessonAgentState`. Предполагаемый checkpointer — **PostgreSQL** (`AsyncPostgresSaver`, [pool и инициализация](../src/core/database/__init__.py)), не Redis из старого README. Но при импорте [DI графов](../src/courses/api/dependencies/agents.py) захватывает `checkpointer=None`; последующий `create_checkpointer()` **переприсваивает** переменную модуля БД, не обновляя эту локальную ссылку. Кроме того, [lifespan](../src/core/lifespan.py) пропускает создание checkpointer в worker. При такой сборке графы получают `None`, а описанный выше путь возобновления по сохранённому snapshot нельзя считать работающим; фактический результат запуска требует изолированной проверки.

В [serializer.py](../src/courses/ai/serializer.py) объявлен allowlist с legacy-именами, но в текущей сборке графов этот модуль не импортируется и его `serde` не назначается checkpointer. Если импортировать его при исходном `checkpointer=None`, присваивание `checkpointer.serde` также не сработает. Поэтому наличие allowlist **не доказывает** его применение или совместимость ранее сохранённых состояний; это нужно отдельно проверять при исправлении инициализации и восстановлении checkpoint.

Конкурентность ограничена `TaskGroup` + semaphore: до 3 модулей на экземпляр `CourseAgent`, до 4 уроков на `ModuleAgent`, до 4 блоков на `LessonAgent`. Ошибка дочерней задачи отменяет siblings TaskGroup, но уже совершённые commits/внешние вызовы остаются. Модуль и урок сохраняются в **отдельной** `session_factory()` с commit/rollback, чтобы не разделять `AsyncSession` между дочерними задачами; курс — в сессии задачи. Локально перехватывается `IntegrityError` с rollback, но это не доказательство совпадения уже записанного результата и не отменяет повторную индексацию/LLM-побочные эффекты. Для `generate_module`/`generate_lesson` rank и границы вычисляются до `generation_lifecycle`; ошибки на этой стадии могут не перевести generation session в `FAILED`. Семафоры не являются межпроцессной квотой и не защищают от двух workers с одним thread ID.

## Indexing и поиск знаний

После коммита урока граф вызывает `index_lesson.kiq` ([lesson graph](../src/courses/ai/generation/lesson.py)); отдельная задача [index_lesson](../src/courses/infra/tasks.py) (2 retry, delay 5, timeout 60 с) читает урок, собирает текст через [get_lesson_context](../src/courses/infra/formatting.py) и отправляет в Qdrant с `document_id=lesson:{course_id}:{lesson_id}`, метаданными `course_id`, `lesson_id`, `category=theory`, `document_type=lesson`, `source`. Отсутствующий урок логируется и пропускается. Завершение генерации **не подтверждает**, что индексация закончилась; ошибка публикации/индекса не откатывает SQL-урок. Не видно автоматической переиндексации при ручном `PATCH` урока или удаления старых точек при удалении.

[QdrantRepository](../src/courses/infra/database/repos/vector_repo.py) режет текст (`chunk_size=3072`, overlap=150; [DI](../src/courses/api/dependencies/repos.py)), создаёт dense embedding и sparse BM25 для каждого чанка, upsert в `MAIN_COLLECTION` с детерминированным UUID5 от `document_id:index`; пустой текст пропускается. Поиск — dense + sparse prefetch, RRF и rerank; [knowledge_search](../src/courses/ai/tools/rag.py) задаёт фильтр `course_id` (и опционально `category`). При этом [форматирование результата `read()`](../src/courses/infra/database/repos/vector_repo.py) выводит `claim`, `evidence` и источник, но **не `text`**: проиндексированный текст урока может участвовать в ранжировании, не попадая в возвращаемый текст поиска. `save_knowledge` индексирует утверждения/доказательства с хешем от курса, категории, URL и текста claim. Детерминированный ID переиспользует существующие чанки, но не удаляет лишние при сокращении текста. [lifespan](../src/core/lifespan.py) подготавливает PostgreSQL-checkpointer и при отсутствии создаёт коллекцию Qdrant с векторами `dense`/`bm25`; это не безопасный тестовый smoke-check: там же миграции и bootstrap CLI.

| `POST /progress/theory-sessions/{uid}` (201), `PATCH /progress/theory-sessions/{theory_session_id}` (200), `GET /progress/theory-sessions/{uid}/users/{user_id}` (200)                                    | Создать по lesson ID; редактировать свою сессию; читать историю по lesson/user с query-фильтрами                                                                                   | READ курса через lesson; update: identity + проверка `session.user_id`; GET — course-access с permission теоретической сессии      | [theory_session.py](../src/courses/api/learning/v1/theory_session.py)                                        |

`course_access` ([зависимость](../src/courses/api/dependencies/access.py)) извлекает владельца курса через `read_course_ownership(uid)`, роль текущего участника и вызывает [политики](../src/courses/application/catalog/policies.py): READ — создатель/участник, UPDATE — создатель/teacher, DELETE — создатель. Для create модуля используется `CREATE` с ресурсом курса: отдельно проверять наличие зарегистрированной policy для этого permission — при отсутствии `authorize` может опираться на глобальное право. Permission/JWT не заменяют проверки связности ID: `lesson_id` в заданиях не привязан явно к `uid` в endpoint; `module_id`/`lesson_id` в прогрессе также требуют сквозной проверки parent-child. `course_access` сам по себе не доказывает совпадение `identity.organization_id` с организацией курса. Для проверки практик по `practice_id` необходима отдельная проверка владельца в глубине агента/репозитория, в HTTP-контракте её нет. [Обработчики ошибок](../src/shared/api/exception_handler.py): `DomainError` → `error.code/message/details` по его статусу; `ValueError` → 400 `error.grant`; обычный `HTTPException` → `detail`; FastAPI validation → 422 `detail`. Не смешивать эти формы.

## Тесты, ограничения и открытые вопросы

- Есть [unit tests](../tests/unit/courses/) сущностей, ранжирования/CRUD модуля и урока, прогресса и отдельных AI-сценариев, а также [integration tests](../tests/integration/courses/) SQL-репозиториев, [e2e read API](../tests/e2e/test_courses_read_api.py) и [manual](../tests/manual/) генерации/индексации. **Наличие файлов не подтверждает покрытие нынешнего кода:** например, [тест practicer](../tests/unit/courses/test_practicer.py) и [тест progress](../tests/unit/courses/test_progress.py) импортируют прежние пути `src.courses.agents`/`src.courses.domain.entities`, а [integration test курса](../tests/integration/courses/test_course.py) — прежний доменный путь. [Тест theory ownership](../tests/unit/courses/test_theory_session_ownership.py) использует AST прежнего контракта (`_identity`, `HTTPException`, `PUT`) и помечен xfail; его нельзя считать подтверждением нынешнего endpoint. Старое утверждение README об отсутствии тестов неверно, но их текущее прохождение не проверялось.
- Для unit/integration запускайте из `backend/` с Python 3.14+ и настроенным окружением: даже collection может импортировать настройки и соседние модули; integration fixture использует Testcontainers PostgreSQL/Redis и Docker. E2E требует отдельного запущенного тестового API; manual генерация требует внешних LLM/очереди/векторного хранилища. Не используйте полный lifespan как безопасный smoke-test. В рамках написания документации поведенческие тесты не запускались.
- Не гарантированы атомарность SQL ↔ брокер ↔ Qdrant, единственность выполнения графа при конкурентных worker, автоматическая повторная индексация после правок/удалений, завершение всех удалённых вызовов при отмене, общая квота на fan-out. Нужно отдельно проверять возможные дубли/устаревшие знания при retry и миграцию checkpoint после переименования классов; [объявленный, но не подключённый serializer allowlist](../src/courses/ai/serializer.py) содержит старые пути. Подтверждение совместимости накопленных checkpoint требует теста на реальных сохранённых состояниях.
- Требуют проверки/решения продукта: публичность `GET /courses/{course_id}` (не только published), организация и целевой parent при move, связь `lesson_id` с `module_id` и ownership `practice_id`, смысл `CREATE`-policy при ресурсном доступе, начальный статус ручного курса и желаемая семантика повторной генерации. Это зафиксированные ограничения/неопределённости, а не обещания исправления.
